01

この機能でできること

5つの処理が完全自動

じゃらん予約のキャンセル発生時、Slack に 1回投稿するだけ で以下が すべて自動で完結 します。

  • Square 自動返金（札幌じゃらん事前決済の場合のみ）
  • 会計起票（キャンセル料を売上計上、返金額を支出計上）
  • 予約ステータス更新（reservations.status = cancelled）
  • じゃらん決済DB 更新（jalan_payments.status = refunded）
  • 支払い管理スプシ更新（札幌のみ）
💡 ポイント Square Dashboard を開く必要はありません。返金もこちらが指示するだけで Bot が実行します。
02

事前準備

投稿前に確認する2項目

① 予約番号を確認

じゃらんからのキャンセル通知メール、または HANDYMAN APP の予約データから取得します。

例: R0DCXBRD

② キャンセル料率を確認

じゃらんからのキャンセル通知メールに記載の キャンセル料率 を確認します。

不明な場合は本マニュアル 06章「OTAキャンセルポリシー早見表」 を参照。

⚠️ 注意 キャンセル料率は 必ずOTAからの通知メールを正 としてください。早見表は目安です。OTA側の判断（特例措置など）で異なる場合があります。
03

Slack 投稿フォーマット

3行（理由は任意で4行）

投稿先チャンネル

店舗チャンネル
札幌店 #payment_sapporo
那覇店 #payment_naha

※ どちらのチャンネルに投稿しても Bot が処理します。普段使っている店舗のチャンネルでOKです。

投稿テンプレート

キャンセル 予約番号：[予約番号] キャンセル料率：[0〜100の整数] 理由：[任意・自由記述]
🚫 投稿時のルール
  • 1行目は必ず キャンセル から始める
  • キャンセル料率は 0〜100 の整数（小数や記号は不可）
  • スレッド返信ではなく 新規メッセージとして投稿
  • 1度に1予約のみ（複数予約をまとめて書かない）
04

実践例（4パターン）

頻出ケースの完全例

例1 札幌 札幌じゃらん 50% キャンセル （最頻出）

📥 Slack に投稿する内容

キャンセル 予約番号：R0DCXBRD キャンセル料率：50 理由：お客様都合

📤 Bot が自動実行

  • Square で半額返金
  • キャンセル料を売上計上
  • 返金額を支出計上
  • 予約をキャンセル状態に
  • スプシ「🚫キャンセル(返金済)」

例2 札幌 無料キャンセル（料率 0%）

📥 投稿内容

キャンセル 予約番号：R0XXXXXX キャンセル料率：0

📤 Bot 動作

  • Square 全額返金
  • 会計起票なし
    （売上も支出も発生しないため）
  • 予約をキャンセル状態に

例3 札幌 全額キャンセル料（料率 100%・無連絡など）

📥 投稿内容

キャンセル 予約番号：R0XXXXXX キャンセル料率：100 理由：無連絡

📤 Bot 動作

  • Square 返金なし
  • 全額をキャンセル料として売上計上
  • 予約をキャンセル状態に

例4 那覇 那覇店じゃらん（事前決済なし）

📥 投稿内容

キャンセル 予約番号：DY00000000XXX キャンセル料率：50

📤 Bot 動作

  • Square 返金なし
    （事前決済なしのため）
  • キャンセル料を nha_accounting に売上計上
    （paid=未入金）
  • 予約をキャンセル状態に
💡 店舗の自動判定 予約番号を入力するだけで Bot が札幌店・那覇店を自動判定します。スタッフが店舗を指定する必要はありません。
05

Bot からの応答

投稿の1〜2分後にスレッドで通知

✅ 成功時の応答例

✅ キャンセル処理完了 予約番号: R0DCXBRD / エノモト ハヤト様 利用日: 2026-04-29 / 元金額: ¥6,650 キャンセル料率: 50% → キャンセル料 ¥3,325 / 返金額 ¥3,325 ✅ Square 返金実行 (refund_id: xxx-xxx-xxx) ✅ 予約をキャンセル状態に更新 ✅ じゃらん決済DB 更新 ✅ 会計起票完了 (売上 ¥3,325 / 支出 ¥3,325) ✅ 支払い管理スプシ更新

❌ 失敗時の応答例

❌ キャンセル処理失敗 予約番号: R0DCXBRD エラー: Square 返金 API がタイムアウトしました ⚠️ 以下の作業は実施されていません。手動対応が必要です: - Square 返金（手動で Square Dashboard から実行してください） - 会計起票（管理者にエスカレーション） 詳細はシステム管理者にご確認ください。

07

エラーが出た時の対処

よくある6パターン
エラーメッセージ原因対処
予約番号が見つかりません 予約番号のtypo / 既に物理削除済み 予約番号を再確認して再投稿
キャンセル料率の値が不正 0〜100以外の値・小数・記号 整数で0〜100の値を入れて再投稿
既にキャンセル済み 同じ予約に対して2回目の投稿 1回目の処理で完結。追加対応不要
未決済の予約です 事前決済前にキャンセル発生（札幌じゃらん） 会計処理は不要。jalan_payments を直接 cancelled に変更（管理者）
Square 返金失敗 Square API タイムアウト / トークン期限切れ システム管理者にエスカレーション
DB 書き込み失敗 Supabase 接続エラー 5分待って再投稿（自動リトライ済の可能性あり）
08

絶対ルール（厳守）

守らないと会計が二重に乱れます
🚫 やってはいけないこと
  • Square Dashboard で先に手動返金しない（Bot が二重返金を試みる原因になります）
  • 会計タブで先に手動起票しない（Bot が同じ仕訳を作って二重計上になります）
  • 同じ予約番号で複数回投稿しない（料率を間違えた場合は即座に管理者へ連絡）
  • キャンセル料率を勘で入力しない（必ずOTAキャンセル通知メールを確認）
✅ 必ずやること
  • OTA からのキャンセル通知メールでキャンセル料率を確認
  • Slack #jalan_payment に正しいフォーマットで投稿
  • Bot のスレッド返信を確認し、すべて ✅ になっていることをチェック
  • 1つでも ❌ があれば管理者にエスカレーション
💡 投稿が間違っていた場合の緊急対応

Bot は投稿後 1〜2分以内に処理を開始 します。投稿ミスに気付いたら、その瞬間にシステム管理者へ 電話または直接連絡 してください（Slack だけでは間に合わない可能性があります）。Bot が処理を開始する前であればキャンセル可能です。
