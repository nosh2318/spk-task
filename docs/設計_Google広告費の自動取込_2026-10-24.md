# 設計メモ：Google 広告の日別費用を自動で取り込む（2026-10-24）

オーナー指示（10/24 チャット）：「ダッシュボードにある集計が更新されない。ダッシュボードにある情報は全てメイン」＝ダッシュボードの数字は常に最新の正本であること。

## 1. 今の問題（確認済み）
- 集客ツール mkt.html の Google 広告（表示・クリック・費用・予約）は、`mkt_docs`（collection=adsdaily, doc=naha/sapporo/takamatsu/other）の `rows` を表示している。中身は 10/21 に書き写した 10/20 までの写しで、誰も更新しない。
  - 例：那覇 10 月の Google 広告費 画面 ¥273,821 ／ Google 広告の実画面 ¥314,898（10/1〜24、10/24 06:2x 読取）。
- HP 件数・売上と月の広告費総額は、すでに開くたびに正本（予約台帳・*_app_settings.hp_adspend_*）から読んでいる＝問題なし。

## 2. 案：Google 広告スクリプト → Edge Function → main の新表 1 つ
1. **新表 `public.ads_daily`**（main）
   - 列：`day date, account text, campaign text, impressions int, clicks int, cost int（円）, conv numeric（予約完了_new_re＋NewSite_予約完了 のみ）, updated_at timestamptz`
   - 主キー `(day, account, campaign)`。外部（Google）の事実の写し先はここ1か所だけ。人が編集する列はない（＝機械が上書きしてよい唯一の種類のデータ。LEDGER-ONE §3.2 に抵触しない）。
   - RLS 有効。読取＝本部メンバー（既存 `private.hq_is_me()` と同じ判定）のみ。anon 不可。書込はポリシーなし（EF の secret のみ）。
2. **Edge Function `ads-ingest`**（main・verify_jwt=false）
   - POST {account, rows:[{day,campaign,impressions,clicks,cost,conv}]}。ヘッダー `x-ads-key` を EF の secret `ADS_INGEST_KEY` と照合（不一致 401）。
   - 受けた行だけ `(day,account,campaign)` で upsert。日付は直近 35 日以内のみ受け付け（初回の取込だけ `backfill=true` で 2026-02-01 から）。削除はしない。
   - 書込件数をログに出す。
3. **Google 広告スクリプト**（HANDYMAN 297-730-9476・KEYDROP 833-892-3668 の各アカウントに1本ずつ・毎日 1 回 06 時台）
   - GAQL：`campaign.name, segments.date, metrics.impressions, metrics.clicks, metrics.cost_micros`（直近 7 日・Google 側の後日修正を拾うため毎回 7 日分を送り直す）＋予約件数は `segments.conversion_action_name` で上の2つに絞る。
   - UrlFetchApp で ads-ingest に POST。鍵はスクリプト本文に置く（Google 広告スクリプトには置き場所が他にない）。
4. **mkt.html**：HP 件数と同じ方式で、開くたびに `ads_daily` を読み、店ごとに日別合計して `rows` を差し替える（putHP/putAd と同型の putRows）。店の割り当てはキャンペーン名で：`札幌`→札幌、`高松`→高松、`全国`→那覇、`Performance Max_202506`→那覇（10/24 確認：アセットグループの広告文が「那覇空港近くのレンタカーならHANDY MANへ」・「沖縄」）、それ以外→「その他」（画面に出して気づけるようにする）。BUDDICA（パートナーの表を貼る方式）は変えない。

## 3. 影響元
- 書込：新表 ads_daily のみ（ads-ingest からだけ）。既存の表・関数・cron は変更しない。mkt_docs の adsdaily.rows は残す（読まなくなるだけ。戻し用）。
- 読込：mkt.html のみ。hp-acquire.html・3店 MTG・cost-cpa は月の総額（hp_adspend_*）を使っており影響なし。
- Gmail は使わない（取込 GAS のクォータに影響なし）。新しい cron なし（Google 広告側のスケジュール）。
- 新しい鍵 1 つ（ADS_INGEST_KEY）。これで出来ることは「ads_daily に広告の数字を書く」だけ。Google 広告アカウントに入れる人（代理店を含む）には見える。

## 4. 戻し方
- mkt.html を git revert（mkt_docs の写しを読む元の形に戻る）。
- Google 広告スクリプトを停止。EF を削除または secret を外す。表は残しても害なし（drop は別途許可）。

## 5. オーナー判断が要るもの
- Google 広告スクリプトを入れること（本番の広告アカウントへの追加）。
- 「P-MAX_202506」（6月から配信中・今月 ¥30,020）はどの店の分か。
- 毎週月曜の検索データ（runs）も古い claude.ai 集客ツールに書かれ続けている。同じ考え方で Supabase に向け直す（別の設計メモ）。

## 6. omni-review（2026-10-24）＝条件付きでよい → 反映
1. 読取範囲＝mkt_read と同じ「authenticated かつ not kyoritsu_is_me()」（今の集客ツールを見られる人＝同じ）。`revoke all on public.ads_daily from public, anon, authenticated; grant select to authenticated;`＋select ポリシー＋kyoritsu_deny restrictive。書込ポリシーなし（service_role のみ）。読めない時に mkt_docs の古い写しへ無言で戻さない（「読めません」と出す）。
2. 主キー `(day, account, campaign_id)`。キャンペーン名は属性列。店割当は campaign_id→店 の明示マップ（mkt.html 定数）。未割当は「その他（キャンペーン名）」で画面に出す。初期マップ：Search_202506_全国・Performance Max_202506→那覇（広告文で確認する）、名前に札幌/Sapporo→札幌、高松→高松。
3. 鍵はアカウント別に2本（ADS_KEY_HDM／ADS_KEY_KD）。EF は鍵から account を決め、body の account は信用しない。鍵未設定なら拒否。受付は日付形式・直近35日・最大500行・数値≥0・名前長さ上限。初回の過去分取込は一時鍵で1回だけ（終わったら外す）。鍵の作り直し＝EF secret を差し替え→スクリプト本文を差し替え。
4. 表示・クリック・費用は直近7日、予約（metrics.all_conversions・2つの予約完了アクション）は直近30日を毎回送る（GAQL は2本）。
5. audit トリガーは付けない（外部の写し・人の列なし。updated_at と EF ログで追跡）。
6. mkt.html は rows だけでなく「○日まで」（to）と「○確認」（checked）も ads_daily から差し替える。未割当分（other）も作る。
7. 実施前に両アカウントのタイムゾーンが JST か確認（違えば日付がずれる）。

## 7. 2026-11-02 完成させる（オーナー「おk」・ORG-20261102-062354-391）
10/24 に EF ads-ingest と secret までで止まっていた。表 ads_daily は本番に無く、mkt.html も読まず、広告スクリプトも未設置で、画面は 10/20 の写しのまま。速報との不一致で判明。
1. 表と関数：ads_daily_20261024.sql をそのまま適用（§6 の条件反映済み）。
2. mkt.html：開くたびに ads_daily_read を読み、HDM 口座分だけ店別に集計して adsdaily の rows／to／checked を差し替える。ads（直近30日・キャンペーン別）と all.unassigned も同じ集計で差し替える（ads は週次の mkt-ingest の対象外で、同じく止まっているため）。DB には書かない。読めない・空の時は今の表示のまま。RPC は1000行上限なのでページ読み。
3. 日単位の差し替え：ads_daily にある日付だけ置き換え、無い日付は mkt_docs の値を残す。過去分取込後は全部 ads_daily になる。
4. 店の割当：§6-2 は campaign_id の明示マップだが、ID は最初の取込まで分からないため、まずキャンペーン名の規則（札幌/sapporo→札幌、高松→高松、全国・Performance Max_202506→那覇）にする。当たらない分は「どの店か分けられない広告」に出して隠さない。
5. Performance Max_202506 は那覇に入れる（§5 の未決。代理店の速報が沖縄 P-Max として報告しているため）。那覇の Google 広告の数字はこれまでより増える。
6. KEYDROP 口座は今回対象外（店集計は account='hdm' のみ）。スクリプトは HDM 口座に1本。
7. キャンペーンの状態・メモ（不承認など）は ads_daily に無いので、差し替え後は出さない（古い文言を残さない）。
8. 戻し：mkt.html を revert／スクリプト停止／ads_daily_20261024_rollback.sql。過去分取込後は ADS_KEY_BACKFILL を外す。
